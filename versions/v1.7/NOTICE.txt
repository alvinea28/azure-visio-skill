EXACT OFFLINE RASTERIZATION METHOD
All PNGs were rendered directly from the original, hash-verified SVGs using
the existing installed resvg_py 0.5.0 svg_to_bytes, skip_system_fonts=True,
dpi=96, without network access or system-font loading. No original was edited.
The longest edge is exactly 256 pixels. If original aspect >= 1, width=256 and
height=round(256/aspect); otherwise width=round(256*aspect) and height=256.
Only in-memory root width and height are set to those integer pixel dimensions.
Every original viewBox is unchanged. For the sole SVG without a viewBox
(azure-9b014206d93a, Foundry Control Plane), original width=18 and height=18
provide the equivalent full-viewport viewBox "0 0 18 18".
Default xMidYMid meet is retained: rounding adds transparent padding, not
distortion or clipping. This matches the earlier vetted sizing method and
avoids intrinsic-size rounding/clipping and default dpi=0 physical-unit errors.
Original artwork elements, colors, gradients, shapes, transforms, resources,
orientation, transparency, and full viewport are preserved.
There is no cropping, quantization, palette/color reduction, background fill,
post-render PNG resampling, or post-render PNG re-encoding. Stored PNG bytes
are exactly the rasterizer output, encoded as standard base64 in ordinary JSON.
All icons decode as static, nonempty RGBA PNGs; catalog hashes and dimensions
match payloads; relative canvas/source-aspect error is strictly below 1%.
At a 0.72-inch longest-edge placement, 256 pixels provides about 355.6 dpi.
The lower resolution trades large-format enlargement/detail for compact,
complete offline coverage without runtime SVG dependencies.

COMPANION FORMAT
catalog.json is the complete 715-record JSON array. Its dataFile values point
to ordinary Icon-Data-N.json companions with schemaVersion=1,
kind="azure-visio-png-data", and images mapping IDs to standard base64 PNGs.
Catalog path values are logical PNG identities, not required on-disk files.
No nested archives, executable code, dependencies, wheels, native modules,
original SVGs, or build helpers are included in the deliverable companion files.
The original archives, SVGs, and prior source terms remain only in the separate
offline build location. Local verification used Pillow 12.3.0 / ReportLab 4.5.1;
execution in Microsoft Cowork or ReportLab 5.0.1 is not claimed.
